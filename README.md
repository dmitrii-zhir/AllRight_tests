# AllRight_tests

E2E-тести реєстраційного квіза [AllRight](https://stage.allright.com/) на Playwright + TypeScript.

Тест проходить квіз реєстрації від початку до кінця й підтверджує бізнес-результат
(створений користувач + заброньований пробний урок) напряму через API.

## Вимоги

| Інструмент | Версія |
|---|---|
| Node.js | 18 або новіше (перевірено на 24.x) |
| npm | будь-яка, що йде в комплекті з Node |

## Розгортання

```bash
git clone https://github.com/dmitrii-zhir/AllRight_tests.git
cd AllRight_tests

# 1. Залежності проєкту
npm install

# 2. Браузер для Playwright (конфіг використовує лише Chromium)
npx playwright install chromium
```

Другий крок обов'язковий: `npm install` ставить лише бібліотеку Playwright,
а самі бінарники браузерів завантажуються окремою командою.

## Запуск тестів

У `package.json` немає npm-скриптів, тому команди викликаються через `npx`:

```bash
# Усі тести (headless)
npx playwright test

# З видимим вікном браузера — зручно спостерігати за проходженням квіза
npx playwright test --headed

# Інтерактивний UI-режим (покроковий перегляд, time-travel)
npx playwright test --ui

# Режим налагодження з інспектором
npx playwright test --debug

# Конкретний файл
npx playwright test tests/allright.spec.ts
```

### Звіт

Конфіг використовує HTML-репортер. Після прогону:

```bash
npx playwright show-report
```

Звіт зберігається в `playwright-report/`, артефакти невдалих прогонів — у
`test-results/`. Обидві теки в `.gitignore`.

## Структура проєкту

```
fixtures/
  all-right-quiz-page.ts   Page Object квіза: проходження + перевірка через API
  my-tests.ts              Кастомна фікстура allRightQuizPage
tests/
  allright.spec.ts         Сценарій: пройти квіз і підтвердити бронювання
playwright.config.ts       baseURL, проєкт chromium, HTML-репортер
tsconfig.json              strict-режим + аліаси шляхів (@fixtures/*, @tests/* тощо)
```

Імпорти використовують аліаси з `tsconfig.json` (наприклад,
`import { test } from '@fixtures/my-tests'`) — Playwright резолвить їх
самостійно, додаткове налаштування не потрібне.

## Що перевіряє тест

1. Проходить квіз реєстрації, розпізнаючи тип кожного кроку **за структурою**
   (роль елемента, тип інпута), а не за фіксованою послідовністю — квіз
   постійно змінюється через A/B-тести.
2. Перехоплює `POST /api/v1/users` і зберігає ID створеного користувача.
3. Після завершення квіза перевіряє через self-service API:
   - `GET /api/v1/users/:id` — користувач існує й не позначений видаленим;
   - `GET /api/v1/lessons?filter[student_id]=:id` — пробний урок заброньовано.

Квіз має два структурно різні екрани завершення (дашборд із самостійно
обраним часом уроку або "Дякуємо!" — коли час підбирає адміністратор вручну).
У другому варіанті урок на момент завершення ще не заброньовано, тому перевірка
кількості уроків свідомо пропускається.

## Важливі нюанси

- **Тести працюють проти живого stage-середовища** (`https://stage.allright.com/`,
  заданого як `baseURL` у `playwright.config.ts`). Кожен прогін створює
  реального користувача з випадковими email і номером телефону (`@faker-js/faker`).
- **Таймаут тесту — 120 секунд** (заданий у самому спеці). Дефолтних 30 секунд
  Playwright не вистачає: повний флоу займає ~48 секунд і включає десятки
  мережевих переходів.
- **Повтори (retries) увімкнені лише на CI** — локально тест виконується один раз.
